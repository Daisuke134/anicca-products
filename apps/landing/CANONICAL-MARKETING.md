## Homepage entity schema + Markdown negotiation (2026-11-17)

GeoReady audit (score_version 2) measured the homepage at 71/100 with schema 7/14 and brand_entity 4/12: `pages/en.html` carried only a WebSite JSON-LD block, so the Organization/SoftwareApplication entities the root layout declares never reached `/` or `/en`. Canonical fix in Daisuke134/anicca PR #9377 (merged as `9fcad256f37d6e86958794e371c5d863030ad1de`, the current pin above): `pages/en.html` now ships the same Organization + SoftwareApplication `@graph` block as the root layout (verified sameAs only: GitHub + App Store; contactPoint contact@aniccaai.com), and the title/og:title lead with the brand (`Anicca — an AI lab to end suffering: ...`). The route-manifest sha256 for `pages/en.html` was refreshed for both export paths.

Markdown content negotiation for `/` and `/en` is served by the regular Netlify Function `netlify/functions/markdown-home.mjs`, reached through forced `[[redirects]]` rewrites in both netlify.toml files (the same pattern as `/apple-rss/*`): requests with `Accept: text/markdown` receive a Markdown rendering of the homepage (kept in step with `pages/en.html`); all other requests receive the static homepage asset unchanged. An Edge Function version (`netlify/edge-functions/markdown-home.js`, same behavior) also exists, but the GHA manual deploy (`netlify deploy --dir=out --functions=netlify/functions --no-build`) did not activate it in production (measured 2026-11-17 on deploy 6afbdf6f of commit 877de0de0: `Accept: text/markdown` kept returning text/html), while regular functions deploy reliably through the explicit `--functions` flag — hence the function + rewrite is the operative mechanism, and the edge function is kept as a no-conflict duplicate (it would run first with identical behavior if a future deploy path activates it). Netlify redirect rules cannot condition on the Accept header (Country/Language/Role/Cookie only), which is why the negotiation itself lives in the function. No verified LinkedIn company page exists, so no LinkedIn URL is declared in sameAs; adding one is the remaining brand_entity/KG item if a company page is created.
